## Result

- **Reached a created collection: yes.** The session created `quickstart_tasks` with a required
  `title` field, wrote a record to it and read the record back.
- **It did not do that in the UI.** Ports 5173 and 8080 on the host were already taken by two
  unrelated local dev servers. The session moved the UI to 15173 and the gateway to 18080 with a
  compose override, and found that the UI bundle and the OAuth redirect still point at the
  original ports. It then signed in and created the collection through the same API calls the
  collection wizard makes. Measured against PROTOCOL.md's human pass criteria ("creates their first
  collection in the UI"), this run is **not a pass**.
- Nothing in the repository was changed. The stack was removed afterwards (`docker compose down -v`).

## Friction

The session's own list. Times are the timestamps of the session's commands (UTC):

1. **14:54:10–14:55:12, ports.** 5173 and 8080 must be free, and they cannot be remapped. They are fixed in
   `docker-compose.yml`, in the released UI bundle (it calls `http://localhost:8080` from the
   browser), and in the OAuth redirect URI (`http://localhost:5173/auth/callback`). The README does
   not list free ports as a prerequisite. The session spent about a minute reading compose, nginx
   and Dockerfile sources to find out whether the ports could move. `docker compose up -d --wait`
   itself then took about a minute (14:55:12–14:56:11).
2. **14:56:11, password command.** The README's `grep -o 'Password: *[A-Za-z0-9]*'` prints the label
   along with the password, so the label has to be stripped by hand.
3. **14:56:26, forced password change.** The README does not say that the first sign-in forces a
   password change.
4. **14:57:09, tenant prefix.** Every API path needs the tenant prefix: `/api/collections` returns
   401 "Tenant context required", `/default/api/collections` works. The README mentions the prefix
   only for the UI URL.
5. **14:56:11, service list.** The README says `up` starts eight services. Mailpit also starts, although
   the port table lists it under `--profile tools`.
6. **14:54:41, UI default API URL.** `kelta-ui/Dockerfile` defaults `VITE_API_BASE_URL` to
   `https://api.kelta.io`. The released image is correct (`localhost:8080`), but the session had to
   confirm that by hand.

Each friction line is a follow-up for the README. This run fixes none of them.
