# Capability Status Map

What actually works vs. what is a stub. **Check this before touching a subsystem.** One row per
capability: what works, what doesn't, where to start reading. Verify against code, and move or
edit the row in the same PR when a change shifts it.

- Per-PR history, test names and design rationale that used to live in these rows are in
  `.claude/docs/_archive/status-history-2026-10-11.md` (verbatim snapshot).
- Spec paths are relative to `.claude/docs/specs/`; shipped specs live under `_archive/`.
- Before calling something a stub, verify reachability: a 2026-07-02 audit found most
  "backend missing" rows were real controllers with **no gateway static route**
  (`RouteConfigService`) — the UI 404'd, the code existed.
- "Security — not auto-merged" marks surfaces whose changes must never get auto-merge.
- No capability is currently UI-only with a missing backend (🔴). If one appears, add a
  "🔴 UI complete, backend missing" section rather than hiding it in 🟡.
